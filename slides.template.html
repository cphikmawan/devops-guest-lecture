Apa itu DevOps?

Spoiler: bukan cuma hafal perintah docker

🤝 Culture

Dev & Ops bekerja bersama, bukan saling lempar tanggung jawab. Shared ownership atas delivery & reliability.

⚙️ Automation

Apapun yang dilakukan >1x harus diotomasi. CI/CD, IaC, CaC. Bukan manual SSH ke server prod.

📊 Measurement

Kalau tidak bisa diukur, tidak bisa diperbaiki. SLO, error rate, latency. Semuanya harus termonitor.

🔄 Continuous Loop

Build → Test → Deploy → Monitor → Fix → ulang. Feedback loop yang cepat = rilis yang lebih aman.

"DevOps engineer yang baik membuat dirinya sendiri tidak dibutuhkan, karena semuanya sudah terotomasi."

Realita vs Ekspektasi

❌ Ekspektasi saat kuliah

  • Semua teori kuliah langsung terpakai
  • Langsung jadi senior engineer
  • Hafal tools = punya skill
  • Sertifikasi = garansi keterima kerja
  • Coding terus sepanjang hari

✅ Realita di lapangan

  • 80% learning on the job
  • 3–6 bulan baru benar-benar "ngerti flow"
  • Problem-solving > tool knowledge
  • Portfolio > tumpukan sertifikat
  • Meeting, docs, dan debugging sama banyaknya
"Yang bikin kamu diterima: kemampuan belajar cepat, bukan IPK."

Review Mini Project

4 Studi Kasus, dilihat dari kacamata industri

4 Studi Kasus

#1 HA Load Balancer

War tiket konser, server down tiap ada lonjakan traffic. Solusi: LB + 4 Workers + Docker + Terraform + Ansible.

#2 HA Database

E-commerce DB single point of failure. Solusi: ProxySQL + Master-Slave replication + SSL + backup otomatis.

#3 CI/CD Pipeline

Rilis manual = chaos. Solusi: Jenkins + GitHub + Docker Scout + Ansible + Jenkinsfile + notifikasi.

#4 Observability Stack

Tidak tahu performa sebelum launch. Solusi: Prometheus + Grafana + k6 load testing 1.000 VUs.

Semua project punya benang merah: Docker → Terraform → Ansible
#1 High Availability Load Balancer

War Tiket Konser: Server Jangan Down

Arsitektur

 Internet
    │
 [Load Balancer]  ← Nginx / HAProxy
    ├──── [Worker 1: Frontend]
    ├──── [Worker 2: Frontend]
    ├──── [Worker 3: Backend]
    └──── [Worker 4: Backend]

Nilai Tambah

Load testing k6: 1.000 concurrent users. Validasi apakah LB benar-benar distribusi traffic.

3 Tahap

  • Docker: Build image FE+BE, scan kerentanan (docker scout)
  • Terraform: Provisioning 5 VM di Azure + VPC + firewall
  • Ansible: Install Docker, setup LB (round robin)
Di Ajaib: "Ini persis skenario saat IPO stock rush, downtime = miliaran rupiah + teguran OJK"
#2 HA Database + ProxySQL

Database Jangan Jadi Single Point of Failure

Arsitektur

 App Node
    │
 [ProxySQL]  ← query router
    ├── WRITE → [Master DB]
    │               │ replikasi
    └── READ  → [Slave 1] [Slave 2]

Nilai Tambah

Health check otomatis: ProxySQL deteksi kalau slave/master gagal, tanpa downtime.

3 Tahap

  • Docker: App + ProxySQL image, security scan
  • Terraform: 5 VMs + isolated network + firewall rules
  • Ansible: MySQL replication, SSL/TLS, user least-privilege, backup cronjob
"Pattern ini identik dengan yang Ajaib pakai untuk database transaksi. Setiap rupiah harus konsisten"
#3 CI/CD Pipeline + DevSecOps

Dari Commit ke Production, Otomatis dan Aman

Pipeline Flow

 git push
    │
 [Jenkins]
    ├── Build Docker image
    ├── docker scout scan
    │     └── CRITICAL/HIGH? → FAIL ❌
    ├── Push ke Docker Hub
    └── Deploy ke Worker Node ✅

Security di Pipeline (DevSecOps)

  • Scan image sebelum push ke registry
  • Pipeline gagal otomatis kalau ada CVE Critical/High
  • Traceability: commit ID → release version

Nilai Tambah

  • Rollback otomatis jika smoke test gagal
  • Notifikasi Slack/Email tiap deploy
"Di Ajaib: ~50–100 deploy/minggu. Tanpa pipeline solid, chaos bisa terjadi kapan saja."
#4 Observability Stack

Kalau Tidak Bisa Diukur, Tidak Bisa Diperbaiki

Arsitektur Monitoring

 App Node
    │ (metrics endpoint)
 [Prometheus]  ← scrape
    │
 [Grafana]     ← visualize
    │
 [Alertmanager] ← alert rules

Load Test dengan k6

1.000 virtual users × 5 menit
Target: p95 latency < 200ms

Golden Signals (4 hal wajib monitor)

  • Latency: seberapa lama request diproses
  • Traffic: berapa banyak request masuk
  • Errors: rate error yang terjadi
  • Saturation: seberapa penuh resource
"Ajaib punya >200 Grafana dashboard. Monitoring bukan optional. Ini survival."

Yang Bikin Nilai Tinggi (dari perspektif industri)

✅ DO ini

  • README yang jelas, setup kurang dari 5 menit
  • Terraform pakai modules + variables
  • Ansible roles yang reusable
  • Security scan diaddress, bukan di-ignore
  • Video demo yang terstruktur

❌ AVOID ini

  • Hardcode credentials di repository
  • Terraform state disimpan locally
  • Tidak ada arsitektur diagram
  • Pipeline yang tidak pernah gagal = tidak ada test
  • Commit dengan pesan "fix" atau "update"
"Reviewer industri yang buka repo kamu: kalau dalam 2 menit tidak ngerti cara jalankannya, langsung skip."

Quiz Time 🎯

5 pertanyaan. Siapa yang paling cepat?

Soal 1 dari 5

Apa kepanjangan dari CI/CD?
A) Continuous Integration / Continuous Deployment ✓
B) Code Integration / Code Deployment
C) Container Infrastructure / Cloud Delivery
D) Commit Instantly / Cloud Deploy
CI = otomatis build & test saat ada commit. CD = otomatis deploy ke environment target.

Soal 2 dari 5

Tool mana yang digunakan untuk Infrastructure as Code?
A) Ansible
B) Terraform ✓
C) Jenkins
D) k6
Ansible = Configuration as Code. Terraform = Infrastructure as Code. Keduanya sering dipakai bersamaan.

Soal 3 dari 5

Apa fungsi ProxySQL dalam arsitektur database?
A) Backup otomatis database
B) Query router untuk read/write splitting ✓
C) Enkripsi data at rest
D) Monitoring slow query log
ProxySQL merouting query: WRITE → Master, READ → Slave. Ini yang bikin DB bisa scale tanpa downtime.

Soal 4 dari 5

Apa "Golden Signals" dalam monitoring?
A) CPU, RAM, Disk, Network
B) Latency, Traffic, Errors, Saturation ✓
C) Uptime, MTTR, MTBF, Throughput
D) SLO, SLA, SLI, Error Budget
Dari buku Google SRE. Kalau 4 hal ini dimonitor dengan baik, kamu tahu kondisi sistem secara keseluruhan.

Soal 5 dari 5

Apa perbedaan utama antara SRE dan DevOps Engineer?

DevOps Engineer

  • Focus: delivery speed
  • Owns: pipeline & automation
  • Mindset: "ship it faster"
  • Background: Dev atau Ops

SRE (Site Reliability Engineer)

  • Focus: reliability & uptime
  • Owns: SLO, error budget, toil
  • Mindset: "stay stable"
  • Background: mostly Software Engineer
"Di Indonesia kebanyakan masih gabungan. Makin mature perusahaannya, makin spesifik role-nya."
